Radiant pairs native HTML behavior with a shared presentation system. Buttons
remain buttons, links remain anchors, and form controls participate in real
forms. Your application owns its data and actions.

## Choose the right element

| Need                                 | Use    | Behavior                           |
| ------------------------------------ | ------ | ---------------------------------- |
| Perform an action                    | Button | Native button activation           |
| Navigate somewhere                   | Link   | Anchor navigation                  |
| Label a control and show help/errors | Field  | Linked label and descriptions      |
| Group a focused task                 | Dialog | Native modal dialog behavior       |
| Group related content                | Card   | A surface with content and actions |

See [Button](/docs/button/) and the [profile form](/docs/recipes/profile-form/)
for complete examples using the installed package.

## Control state deliberately

Use uncontrolled values when the browser should own a control's state. Use
controlled values when React or a form library should own it. Keep an instance
with one owner for its lifetime; remount it deliberately to change ownership.
Radiant supplies presentation and native relationships; your application owns
validation, submission, persistence and feedback.

The profile recipe demonstrates this distinction with native `FormData` and
optional TanStack bindings. Radiant does not require a form library.

## Apply a preset

Use the public `ThemeScope` and a published preset around the relevant subtree:

```tsx
import { Button, ThemeScope, jelly } from '@cognitap/radiant'

export function ThemedAction() {
  return (
    <ThemeScope
      theme={jelly}
      mode="light"
    >
      <Button>Continue</Button>
    </ThemeScope>
  )
}
```

The public `themes` registry contains Radiant, Default, Soft squircle, Expressive, Glass,
Sharp 3D, Jelly and Ticket. Preset implementations live in the library. Try
them in the [interactive gallery](/docs/foundations/theming/#supported-presets)
without changing form behavior.

### Modes

`ThemeScope` accepts `light`, `dark` and `system`. A nested scope can choose its
own theme and mode. The documentation's Appearance control changes the site;
the previews keep their own selections. System mode follows the browser's
color preference through CSS, including before hydration. Explore
[nested scopes](/docs/foundations/theming/#nested-scopes) to inherit a theme,
change only its mode or reset to Default.

<Callout title="Keep presentation separate from behavior">
  Theme choices change presentation. They do not replace application validation, persistence or the
  semantic role of a control.
</Callout>

## Read the package contract

Continue with [theming](/docs/foundations/theming/) for semantic tokens, fonts
and component overrides, or [composition](/docs/foundations/composition/) for
state, events, native hosts, refs and React boundaries.

The library's [0.0.4 system guide](https://github.com/cognitap/radiant/blob/eb1010f4f0031711dc848036dae3596c9f65be04/docs/system.md)

the library's development and regression workspace; these guides own the
public explanations and examples.
