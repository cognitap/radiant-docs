## Start with a label

```tsx
<Field
  label="Work email"
  description="Used for team notifications"
  required
>
  <Input
    name="email"
    type="email"
    autoComplete="email"
    defaultValue="ada@example.com"
  />
</Field>
```

Input renders one native `input`. [Field](/docs/field/) supplies its label,
control ID, descriptions, error and required/disabled metadata. Outside Field,
use a native label with `htmlFor` and `id`. A placeholder is not a label.

## Choose a value owner

`defaultValue` sets the initial browser-owned value. Native form reset restores
it. For React or a form library, pass `value` and update it from `onChange`:

```tsx
const [name, setName] = useState('')
<Field label="Display name">
  <Input value={name} onChange={event => setName(event.target.value)} />
</Field>
```

Initialize controlled text with `''`. Do not pass both value props or switch
ownership during a mount; remount to change owners. A controlled form resets
its application values and validation metadata in `onReset`.

Keep the raw value while editing. Native keyboard shortcuts, selection,
composition events, autofill and change/blur handlers reach the input directly.
Validation and persistence belong to your application.

## Validate and submit

Use native `validity` or your own rules, pass `error` to Field, and focus the
first invalid input through its ref. Add `noValidate` to the form to replace
the browser's popup. Read named values with `new FormData(form)`.

Read-only inputs stay focusable and submit their value, but skip native
constraint validation. Disabled inputs cannot be edited or focused and are
omitted from form data. Field's required/disabled state cannot be undone by its
child. See [Field](/docs/field/) for relationship ownership.

## Motion and customization

The profile example uses public hooks from `@cognitap/radiant/motion/react`:
`useSpringStyle` animates a separate decorative focus cue; `useSpringLayout`
moves dedicated wrappers around changing validation content. Native focus and
input state remain immediate. Theme off and live system reduced motion snap
presentation to its target. See [motion setup](/docs/foundations/motion/).

`className`, typed `style`, native props and `ref` target the actual
`HTMLInputElement`. Keep its focus ring visible. Override local tokens, for
example `style={{ '--rad-input-radius': '999px' }}`.
There is no wrapper, `parts` or Input motion prop.

## Public props

`InputProps` is exported. Identity is `data-slot="input"`, with
`data-control-size` and presence-based `data-invalid` alongside `aria-invalid`.

| Prop                                           | Purpose / default                                                  |
| ---------------------------------------------- | ------------------------------------------------------------------ |
| `type`                                         | Native type; default `text`. Use Checkbox / RadioGroup for choices |
| `value` / `defaultValue`                       | Controlled value or initial browser-owned value                    |
| `onChange`, `onBlur`, `onCompositionStart/End` | Native handlers                                                    |
| `controlSize`                                  | `small`, `medium` (default), `large`                               |
| `size`                                         | Numeric character-width hint; CSS may constrain actual width       |
| `name`, `form`                                 | Native submission name / form association                          |
| `required`, `disabled`, `readOnly`             | Native state; Field can add required/disabled                      |
| `id`, `aria-*`                                 | Field owns its control ID and appends descriptions                 |
| `autoComplete`, `inputMode`, constraints       | Native editing hints and validation                                |
| `className`, `style`, `ref`                    | Actual input customization / ref                                   |
| Other native props                             | Remaining input attributes and events                              |

Value ownership guards apply to text-like types; file and choice inputs keep
native value behavior. Copy source files using their shown paths.
