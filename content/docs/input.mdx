## Edit a native value

Input renders one native `input`, defaulting to `type="text"` and
`controlSize="medium"`. Use it for text, email and other appropriate native
input types. Use [Checkbox](/docs/checkbox/) or [RadioGroup](/docs/radio-group/)
for choice controls.

Input does not decide validation rules or timing. Your application can check
native `validity`, pass Field's `error` and focus the input.

## Labels and state

Use [Field](/docs/field/) for the label, description and error relationships.
Input consumes its IDs and required/disabled state. A placeholder is not a
label. Outside Field, associate a native label with an explicit `id`, or supply
an appropriate accessible name yourself.

A read-only input stays focusable and its value is submitted; a disabled input cannot be edited or
focused and is omitted from `FormData`. Native read-only inputs do not
participate in constraint validation. Neither state is an application permission
check. If both are enabled, disabled behavior takes precedence.

## Choose one value owner

Native form reset restores a `defaultValue`. For React or a form library, pass
`value` and update it from `onChange`. Initialize an empty controlled text input with `''`, rather
than `null` or `undefined`. This ownership applies to text-like types; `file`,
`checkbox` and `radio` keep native value behavior.

Do not pass both `value` and `defaultValue`, or switch ownership during a mount.
Remount to change owners. A controlled form's reset handler must reset
application values and validation metadata too.

## Anatomy and public props

The host is the styling, native-prop and ref target: `HTMLInputElement`,
`data-slot="input"`, and `data-control-size`. Invalid state exposes
`data-invalid` and `aria-invalid`. There is no wrapper or `parts` prop.

`InputProps` is exported.

| Prop                                                 | Purpose / default                                                                                |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `type`                                               | Any native input type; defaults to `text`                                                        |
| `value` / `defaultValue`                             | Controlled value or initial browser-owned value; choose one                                      |
| `onChange`, `onBlur`                                 | Native events; text changes still expose `event.target.value`                                    |
| `controlSize`                                        | `small`, `medium` (default), `large`                                                             |
| `size`                                               | Native numeric character-width hint, separate from `controlSize`; layout CSS can constrain width |
| `name`, `form`                                       | Native form-data name and form association                                                       |
| `required`, `disabled`                               | Native state, also inherited from Field                                                          |
| `readOnly`                                           | Native read-only behavior                                                                        |
| `id`, `aria-*`                                       | Native relationships; Field owns its control ID and adds its descriptions                        |
| `autoComplete`, `inputMode`, `min`, `max`, `pattern` | Native hints and constraints for the chosen input type                                           |
| `className`, `style`, `ref`                          | Customization and ref on the actual input; style accepts typed theme tokens                      |
| Other native props                                   | Remaining input attributes/events                                                                |

Keep native keyboard editing, selection, autofill and focus indicators intact.
Server-side validation and persistence belong to your application.

## Use the example in a form

Keep the `controls/` and `profile/` paths when copying. The example needs only
React and Radiant. The [profile recipe](/docs/recipes/profile-form/) uses the
same Input with native FormData or optional TanStack bindings; TanStack is not a
Radiant runtime dependency.
