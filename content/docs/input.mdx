## Usage

Wrap Input in [Field](/docs/field/) for a label, help text and errors.

Use [Textarea](/docs/textarea/) for multiple lines, [PasswordInput](/docs/password-input/) to reveal passwords, or [InputGroup](/docs/input-group/) for icons and actions.

## Examples

### Controlled input

```tsx
function NameInput() {
  const [name, setName] = useState('')

  return (
    <Field label="Name">
      <Input
        name="name"
        value={name}
        onChange={event => setName(event.currentTarget.value)}
      />
    </Field>
  )
}
```

## State

Use `defaultValue` or `value` with `onChange`. Keep that choice until remount. Form reset restores `defaultValue`. Reset controlled values in `onReset`.

## Accessibility

Give each input a label, `aria-label` or `aria-labelledby`. For an error outside Field, set `aria-invalid` and link the message with `aria-describedby`.

## Styling

Set `--rad-input-radius` in `style` to change the corners. See [focus outlines](/docs/foundations/theming/#focus-outlines) for focus and error colors.

## API

Input accepts native input props and events.

| Prop                        | Purpose                                                          |
| --------------------------- | ---------------------------------------------------------------- |
| `controlSize`               | `small`, `medium` (default), or `large`                          |
| `size`                      | Native width hint in characters                                  |
| `required`, `disabled`      | Inherit from Field. Disabled inputs skip focus and submission.   |
| `readOnly`                  | Prevents edits. The input stays focusable and submits its value. |
| `className`, `style`, `ref` | Target the native input, which has `data-slot="input"`           |
