## Usage

Use Input for one line of text, such as a name, email, URL or number. Use [Textarea](/docs/textarea/) for multiple lines, [PasswordInput](/docs/password-input/) for passwords with a reveal action, and [InputGroup](/docs/input-group/) to add icons, buttons or prefixes.

```tsx
<Field label="Work email">
  <Input
    name="email"
    type="email"
    autoComplete="email"
  />
</Field>
```

For codes, tokens or suggestions, use [OTPField](/docs/otp-field/), [TagsInput](/docs/tags-input/) or [Combobox](/docs/combobox/). Choice types belong to Checkbox, RadioGroup and Switch.

## State

Choose one value owner per mount: `value` with `onChange`, or `defaultValue`. Passing both, switching owners or passing `null` throws a TypeError. Use `''` for an empty value, and remount with a new `key` to change owners.

The value submits natively under `name`, and `form` associates an input outside its form. Reset restores `defaultValue`; controlled owners reset their own state in `onReset`.

`disabled` blocks editing and focus and leaves the value out of form data. `readOnly` keeps the value focusable and submitted but not editable. Field's `required` and `disabled` apply to its control, and the control cannot undo them.

## Accessibility

Every control needs an accessible name. Wrap it in [Field](/docs/field/) for a label, description and error, or pass `aria-label` or `aria-labelledby`. A placeholder is not a name. The native input keeps the implicit role for its `type`, such as textbox or searchbox.

Field joins its description and error IDs before the caller's `aria-describedby`. Set `aria-invalid`, or pass `error` to Field, to mark the value invalid.

| Key             | Behavior                           |
| --------------- | ---------------------------------- |
| Tab / Shift+Tab | Move focus in and out              |
| Typing, arrows  | Native editing, selection and IME  |
| Enter           | Submit the enclosing form natively |

## Motion

Input does not animate. Focus and invalid styles change immediately. Animate surrounding content with the hooks in [motion setup](/docs/foundations/motion/).

## Styling

Input renders one native `<input>`, so `className`, `style` and `ref` all target it. It carries `data-slot="input"`, `data-control-size` and `data-invalid` when invalid. Hosted inputs in InputGroup, PasswordInput, OTPField and TagsInput add their own slot tokens.

Override `--rad-input-*` variables in `style`, for example `{ '--rad-input-radius': '999px' }`. Variables cover height, padding, font, color, background, border, radius, corner shape, shadow, placeholder, focus, invalid border and disabled background.

## API

### Input

| Prop                 | Type                                   | Default             |
| -------------------- | -------------------------------------- | ------------------- |
| value / defaultValue | string / number / readonly string[]    | None; one owner     |
| onChange             | `ChangeEventHandler<HTMLInputElement>` | None                |
| type                 | Native input type                      | text                |
| controlSize          | small / medium / large                 | medium              |
| size                 | number; native width in characters     | None                |
| name / form          | string                                 | None                |
| required / disabled  | boolean                                | Field's, else false |
| readOnly             | boolean                                | false               |
| aria-invalid         | Native; mirrored as `data-invalid`     | Field's             |
| className / style    | string / ThemeStyle                    | None                |
| ref                  | `Ref<HTMLInputElement>`                | None                |
| Other props          | Native input attributes and events     | Native defaults     |

Exports `Input` and `InputProps`.
