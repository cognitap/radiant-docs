## Usage

Use ScrollArea for themed scrolling in constrained content. Use plain `overflow: auto` when default scrollbars are fine, and [TableContainer](/docs/table/) for a table's native overflow. Virtualize very long data.

```tsx
<ScrollArea
  aria-label="Messages"
  style={{ height: 160 }}
>
  {messages.map(message => (
    <p key={message.id}>{message.text}</p>
  ))}
</ScrollArea>
```

## State

The browser owns scroll positions. Use the viewport ref's `scrollTo` for application actions; content changes clamp offsets natively. `onScroll` observes the native viewport. Prevent default in `onPointerDown` to cancel bar dragging. ScrollArea has no controlled state and no form value.

## Accessibility

Supply `aria-label` or `aria-labelledby`. The viewport is a named group with `tabIndex=0`; decorative bars share its native keyboard scrolling. Inside Select, Combobox or Menu, set `tabIndex={-1}` to preserve the widget's focus owner. Focused content keeps bars visible.

| Key                            | Behavior                                       |
| ------------------------------ | ---------------------------------------------- |
| Tab / Shift+Tab                | Reach the viewport and its interactive content |
| Arrow keys                     | Native scrolling on the focused viewport       |
| PageUp / PageDown / Home / End | Browser-native scroll navigation               |

## Motion

Thumbs follow native scroll positions directly; dragging adds no easing. Scrollbars fade by opacity. With `visibility="scroll"` they hide 900 ms after scrolling stops; use `always` to keep them shown. MotionProvider has no effect.

## Styling

Root props, ref, classes and typed styles reach the native scroll div. Constrain its height, width or maximum size. `parts.content` styles content; `scrollbar` and `thumb` style their visual spans. Hit areas keep a separate gutter.

Root identity is `scroll-area`; parts use `scroll-area-content`, `scroll-area-scrollbar` and `scroll-area-thumb`. Bars expose `data-axis`, `data-state="visible|hidden"`; thumbs expose `data-dragging`. Root exposes `data-orientation` and `data-visibility`.

Theme hooks: `components.scrollArea.size`, `radius`, `thumbColor`, `trackColor`, or their `--rad-scroll-area-*` variables. Size changes the visible mark within its hit area.

## API

### ScrollArea

| Prop                         | Type / default                                                                       |
| ---------------------------- | ------------------------------------------------------------------------------------ |
| aria-label / aria-labelledby | string; one required                                                                 |
| orientation                  | `Orientation \| 'both'`; vertical                                                    |
| visibility                   | hover / scroll / always; hover                                                       |
| tabIndex                     | number; 0                                                                            |
| parts                        | `{ content?, scrollbar?, thumb?: PartStyle }`                                        |
| className / style            | string / ThemeStyle; the viewport                                                    |
| ref                          | HTMLDivElement                                                                       |
| Other props                  | Native div props and events except role, contentEditable and dangerouslySetInnerHTML |

Exports `ScrollAreaProps`, `ScrollAreaOrientation` (`Orientation | 'both'`) and `ScrollAreaVisibility`.
