## Show optional content

Collapsible renders native `details`. CollapsibleTrigger is its direct-child
`summary`, and CollapsibleContent is the content `div`. Activate the summary
with a pointer, Enter or Space. The marker is decorative; descriptive trigger
text gives the disclosure its name.

The content stays mounted, so reopening preserves an input's value. Closed
content is hidden and skipped by keyboard navigation. Collapsing does not clear
values or submit a form.

Give several Collapsibles the same native `name` to make an exclusive group:
opening one closes the others. A nested disclosure does not toggle its parent.

## Controlled and uncontrolled

With `defaultOpen`, Collapsible owns its state and `onOpenChange` reports
changes. The next example passes `open` with `onOpenChange`, so an outside
button and the summary update the same application-owned state.

Choose one owner per mount; do not pass both `open` and `defaultOpen`, or change
ownership in place. Native `onToggle` observes the details event; use `onOpenChange` to accept a
controlled state change. Do not write the same state through two callbacks.

## Anatomy and customization

| Component          | Native style/ref target | `data-slot` identity  |
| ------------------ | ----------------------- | --------------------- |
| Collapsible        | `details`               | `collapsible`         |
| CollapsibleTrigger | `summary`               | `collapsible-trigger` |
| CollapsibleContent | `div`                   | `collapsible-content` |

Keep the summary directly inside details. Do not wrap it in a button or move it
into another wrapper; native activation and disclosure semantics belong to it.
Never put a button or link inside the trigger.
The root, trigger and content expose `data-state="open" | "closed"`; the root
also has native `open`. CollapsibleContent receives its generated content ID.

Set `--rad-collapsible-padding` in the root's inline style for local padding.
Each named part accepts `className`, typed theme `style` and its own native
ref. Preserve the hidden-content behavior, focus indicator and reduced-motion
alternative when customizing. `useCollapsible()` returns the nearest state or
`null` outside a Collapsible.

## Public props

These contracts match **Radiant 0.0.4**; each named part's prop type and
`CollapsibleState` are exported.

| Collapsible prop            | Purpose / default                                         |
| --------------------------- | --------------------------------------------------------- |
| `open` / `defaultOpen`      | Controlled state or initial local state; initially closed |
| `onOpenChange`              | Receives the next boolean change request                  |
| `onToggle`                  | Native details event observation                          |
| `className`, `style`, `ref` | Customization and ref on the native details               |
| `data-slot`                 | Additional identity tokens; retains the base token        |
| Other native props          | Remaining details attributes/events and children          |

Trigger and Content accept native summary/div props, styles, refs and additive
identities. There is no Button `render` API or native `disabled` prop on this
family. Use [Accordion](/docs/accordion/) when related disclosures need a
selection owner and disabled items. Use [Dialog](/docs/dialog/) for a modal task.

## Use the examples

Install `@cognitap/radiant@0.0.4` and import `@cognitap/radiant/styles.css` once.
Keep the `compositions/` paths when copying. These examples need React and
Radiant only. Basic native details work without JavaScript; controlled state
requires it.

Your application decides whether to retain, clear or persist
the content; disclosure state alone does not own those decisions.
