## Usage

Use Progress for a task advancing toward completion, such as an export or upload. Use [Meter](/docs/meter/) for a measured level in a known range, such as storage or battery. Use [Spinner](/docs/spinner/) for a short wait with no amount and [Skeleton](/docs/skeleton/) for content loading in place.

```tsx
<label htmlFor="export">Export progress</label>
<Progress id="export" value={40} />
<p>40 of 100 items prepared.</p>
```

## State

Progress is read-only. The caller owns `value`; there is no `defaultValue` and no change callback. It is not a form control and submits nothing.

The minimum is always zero. `max` must be finite and positive. A numeric `value` must be finite and between zero and `max`. Invalid values throw a RangeError. `0` means known progress with no work done.

## Accessibility

The native element has the progressbar role. Name it with a `<label htmlFor>`, `aria-label` or `aria-labelledby`; Radiant documents this but does not enforce it. Screen readers announce a percentage unless you set `aria-valuetext`. The fallback content is `aria-valuetext` when given, else "value of max". It is not an accessible name.

Progress adds no live region. Announce milestones such as completion or failure with your own status element, not every update. Set `aria-busy` on the region whose content is changing.

| Key             | Behavior                                 |
| --------------- | ---------------------------------------- |
| Tab / Shift+Tab | Skip the bar, which is not focusable     |
| Arrow keys      | No adjustment; the caller owns the value |

## Motion

Nothing moves. The indeterminate state is a static striped track with a dashed border, so it reads the same with reduced motion.

## Styling

Progress renders one `<progress data-slot="progress">`. `className`, `style` and `ref` target it, and a caller `data-slot` is joined after `progress`. `data-state` is `indeterminate`, `loading` or `complete`; complete means `value` equals `max`. `:indeterminate` also matches with no value.

Override `--rad-progress-*` variables in `style` or `components.progress` in a theme:

```tsx
<Progress
  aria-label="Upload progress"
  value={3}
  max={5}
  style={{
    '--rad-progress-height': '1rem',
    '--rad-progress-radius': '.25rem',
    '--rad-progress-indicator-color': 'var(--rad-color-warning)'
  }}
/>
```

Variables cover height, radius, border width, style and color, track color and indicator color. Forced colors use Canvas, CanvasText and Highlight.

## API

### Progress

| Prop                         | Type                        | Default              |
| ---------------------------- | --------------------------- | -------------------- |
| value                        | number / null; 0 to max     | None; indeterminate  |
| max                          | number; finite and positive | 100                  |
| aria-valuetext               | string                      | None; the percentage |
| aria-label / aria-labelledby | string                      | None; or a `<label>` |
| className / style            | string / ThemeStyle         | None                 |
| data-slot                    | string                      | None; after progress |
| ref                          | `Ref<HTMLProgressElement>`  | None                 |
| Other props                  | Native progress attributes  | Native defaults      |

Not accepted: `defaultValue`, `children`, `role` and the `aria-valuenow`, `aria-valuemin` and `aria-valuemax` attributes.

Exports `Progress` and `ProgressProps`.
