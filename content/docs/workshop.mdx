## A shared workspace

Color, Typography, Spacing & surfaces and Motion edit one theme document. Color builds a complete palette, and Spacing & surfaces shapes the shared geometry.
Typography and Motion have starting controls for the shared workspace. No edits are sent to a server.

**Reset color**, **Reset typography**, **Reset spacing & surfaces** and **Reset
motion** restore that section's baseline (Color returns to the default purple brand,
recommended families and automatic roles) while retaining the other sections and
specimen interactions. Spacing & surfaces returns to Balanced, including the dark
backdrop override. Color owns the canvas color; resetting geometry preserves
it. Component exceptions remain intact.

## Build your color system

Enter an opaque six-digit sRGB **Brand color**. The production OKLCH engine
creates 18 families with 11 shades each. **Exact brand anchor** keeps your input
unchanged at the identified brand stop, reshaping nearby shades. **Regular ramp**
keeps the original as reference metadata instead. Semantic roles may choose
the nearest brand shade with readable text and a visible boundary in each mode,
so your action fill can differ from the original.

Choose **Classic**, **Balanced** or **Expressive** independently for the **Wall
preset** and **Brand ramp preset**. Balanced starts both. Classic preserves the
original calibration; Balanced smooths the anchored ramp with restrained brand
shades and coordinated families; Expressive supplies fuller colors. Choosing a
preset resets only its own vividness/tint/alignment dials and keeps the other
preset, shared tone controls and pinned semantic roles.

Wall and brand vividness each start automatically from the source. Turn either
automatic control off to adjust its own dial. Then explore hue-aware versus shared lightness,
tone distribution, neutral tint and hue alignment. Neutral brands also expose a
hue direction for supporting colors. All output is sRGB; this version does not
accept alpha or Display P3 sources. Invalid hex keeps the last valid theme visible.

The six-family **Working palette** recommends primary, support, neutral, success,
warning and danger colors from the full wall. Change a family to guide automatic
roles, or choose **Use recommended families**. Support and success remain working
colors rather than new component tones.

For precise control, choose a **Role mode** and **Semantic role**, then enter an
exact color or apply a wall shade. Family and stop selectors provide the same
selection by keyboard. Overrides stay pinned across brand and family changes;
**Clear role override** returns the selected role to automatic selection. **Use
automatic roles** clears both modes' overrides. Role mode is independent of the
specimen preview mode. Switching editors preserves your selections.

The contrast report measures the final opaque semantic colors in light and dark
modes, including canvas pairs. It preserves failing choices and explains which
pairs need attention. Inactive-control observations are informational. The report
is not a whole-page accessibility certification: inspect component exceptions,
translucent effects and rendered content in the specimens too. Pending controls
still need contrast. No AI or server request is involved.

## Shape spacing and surfaces

Start with **Balanced**, **Compact**, **Spacious** or **Square & flat**. Each preset
sets this editor’s bounded decisions in both modes and clears previous overrides.
It preserves your colors, fonts, motion, focus settings and component exceptions.
Balanced uses 8px control and 12px panel radii; its backdrop starts at 45% in light
mode and a 65% dark override.

**Spacing multiplier** scales all five shared gaps plus panel padding and gap.
**Control density** scales small, medium and large control heights, horizontal
padding and indicators while keeping font sizes unchanged. Values derive from
Radiant’s neutral baseline; repeated changes never multiply an earlier result.
Use the number fields for precise values or the labeled sliders with arrow keys.
Invalid or out-of-range input keeps the last valid theme.

Control and surface radii and border widths are independent. Border style affects
both; Radio remains circular and Checkbox caps its inherited radius. Elevation
controls passive panel and overlay shadows with mode-specific opacity. Backdrop
opacity controls the black modal backdrop; action shadows and dialog panel
filters remain component exceptions.

**Geometry scope** selects shared defaults, light overrides or dark overrides;
it is separate from specimen preview mode. Shared edits retain mode overrides.
Choose **Use shared…** for one setting or clear the selected mode’s overrides.
Clearing the default dark backdrop override makes it follow the shared opacity.
Switching editors retains the selected scope; resetting this section returns to
shared defaults and the Balanced recipe.

Use **Components** to compare all three sizes and inspect keyboard focus,
disabled/invalid states and the real modal. Check boundaries and hit targets when
reducing density or removing borders. The resolved-values table shows the actual
compiled light/dark shared roles; component exceptions can still override them.
This editor changes theme roles, rather than composing page layouts.

Geometry remains ordinary `control`, `spacing` and `surface` document sections,
so full-theme and selective round trips use the public document APIs. A selective
surface section includes its canvas color, even though Color owns that decision
in the editor. Use the handoff panel below for whole-theme and selective exports.

## Edit typography proofs

Open **Typography** for composed **Article**, **Form**, **Data** and **Landing**
proofs. Prose and UI are text contexts; Body, Headings, UI and Code are font
assignments. The proofs mix these contexts rather than treating them as separate
font scales. Font/role/rhythm controls are the next editor step.

**Edit … copy** exposes the current composition’s headings, paragraphs, labels,
links, lists and supporting copy. Changes are plain text and appear at every
width. Untouched passages retain their inline emphasis and code. Form values,
checkboxes, saved feedback, table filters and landing actions also share one
owner across frames. They stay in memory when switching editors, compositions,
widths or modes. They are not theme settings and do not enter exports or links.

Choose 800, 640, 390 or 320 CSS pixels, or compare **800 + 390px**. Each frame
keeps its real CSS width and reports its display scale when fitted into the
available space. Evaluate reading comfort at 100% display size. Fluid headings
respond to the frame’s local content width. Tables and code scroll inside named,
keyboard-focusable regions; the rest of the composition reflows. The optional
**Text spacing probe** changes only the preview, not exported typography.

**Reset current proof** restores only that composition’s copy and interactions.
Typography’s section reset retains proof copy and values, the other theme
sections and inspection controls. The whole frame’s **Reset preview** restores
everything. Preview mode uses the shared specimen mode below the proofs.

The published 0.0.4 package does not include the DEV-163 text roles. Its proofs
remain semantic and editable with an explicit availability notice. Verify the
new role styling with a matching packed candidate; publication and the exact
public pin belong to DEV-169. Product controls remain real Radiant components;
their role adoption follows in DEV-167. The site supplies layouts and content,
and consumes the package’s semantic text hooks without a second scale/compiler.

## Try fonts

Open **Typography** to try Inter, Source Serif 4, IBM Plex Sans or IBM Plex Mono.
The site hosts pinned normal and true italic files and their complete open font
licenses. Only selected families load; a visible status distinguishes loading,
loaded and failed files. The sample uses the named fallback until loading succeeds.
Changing the trial does not change your theme: choose **Use family in theme** to
apply its family and selected weight. Existing theme sections and component
exceptions remain. The Body family/size controls still edit the shared theme.

Choose Body, Headings, UI or Code as the trial context. Studied combinations show
their accepted starting metrics; unfamiliar fonts and unsupported contexts use
neutral manual settings. Manual sample metrics survive family/context switching.
**Reset context sample** restores only that context's automatic metrics. Sample
copy stays editable. These are starting points, not readability scores.

The weight field retains your requested weight when switching fonts. An unavailable
weight is flagged and cannot be applied to the theme. Italic requires a real
italic file. Inter and Source Serif expose automatic/manual optical size; Plex
Sans exposes its real width axis at 100% by default. Other controls appear only
for verified axes. Sample spacing and axis exploration stay local to the trial;
the family/selected weight and face requirements travel through theme handoff.

**Try a local font file** accepts WOFF2, WOFF, TTF or OTF up to 10 MiB. Set a unique
CSS family name before choosing the file. TTF/OTF metadata supplies available
weight/style/axes where present. For compressed web fonts this trial does not
decode metadata: declare the actual file weight/style and tune manually, with no
inferred axes. A normal-only file has no italic option; an italic-only file can
be inspected but cannot become the shared theme family. Collections are unsupported.

Local files stay in memory. They are never uploaded, saved to browser storage,
embedded in configuration or included in share links. Remove the file or reset
Typography to release it; resetting the preview/reloading also discards it.
A theme can retain a local family requirement after removal, but uses fallback
until that file is provided again. Recipients must supply their own licensed
copy. The handoff setup identifies the required family, selected weights/styles
and missing local file; a family name alone never establishes availability.

The diagnostic line includes Hungarian, Greek, Cyrillic, Arabic and CJK samples.
Some glyphs intentionally fall back: the curated files are not universal script
fonts. A successful load does not certify every glyph, shaping or language.
Inspect the copy you actually need in narrow and wide layouts.

### Load fonts in your app

Radiant never loads fonts. Self-host the required files or use your app's font
loader. Preserve upstream licenses and choose a release/package setup matching
your exported document. For example, with the unmodified Inter variable files:

```css
@font-face {
  font-family: 'Inter';
  src: url('/fonts/Inter.woff2') format('woff2');
  font-weight: 100 900;
  font-style: normal;
  font-display: swap;
}
@font-face {
  font-family: 'Inter';
  src: url('/fonts/Inter-Italic.woff2') format('woff2');
  font-weight: 100 900;
  font-style: italic;
  font-display: swap;
}
.your-text {
  font-family: 'Inter', system-ui, sans-serif;
  font-synthesis: none;
  font-optical-sizing: auto;
}
```

Use the actual file's supported descriptors. Plex Sans additionally needs
`font-stretch: 85% 100%` on each face to expose width matching. Keep width at 100%
unless you deliberately choose another supported design. Optical sizing has an
effect only when the file contains that axis. For a local trial's chosen CSS name,
use that exact family in your app's `@font-face`; substitute your own file URL.

The workshop uses the [CSS Font Loading interface](https://www.w3.org/TR/css-font-loading/)
to await specific faces, and reads TTF/OTF axes from their
[OpenType variation table](https://learn.microsoft.com/en-us/typography/opentype/spec/fvar).
Public URLs, exact checksums and license links are in the
[asset manifest](/fonts/workshop/manifest.json).

## Take your theme

**Copy typed theme** is the primary handoff: a typed `ThemeDocument` and the
compiled Radiant `theme`, ready for `ThemeScope`. Import the package’s compiled
styles once in your app entry and use a release that includes the document APIs.
The optional reset is separate. Radiant 0.0.4 provides these APIs; the site header identifies the installed
package used by every specimen and export.

**Download configuration** saves the complete authoring document, palette/font
metadata and available color/geometry recipes, including both named color
presets and their dial overrides, as JSON. Import the file or paste
its JSON to continue editing. Full themes/configurations replace the theme and
identity; specimen interactions and preview controls stay unchanged. Plain theme
documents have no generator recipes, so their imported Color and Geometry values
remain intact until you explicitly reset those editors. Typography and Motion
continue editing supported leaves while preserving other authored values.

Selective files contain exactly the chosen public sections. **Merge supplied
leaves** keeps omitted values; **Replace supplied sections** removes omitted
values in those sections, preserving all other sections and the destination
identity. Select `components` explicitly to transfer component exceptions.
`surface` includes both canvas and geometry; select `color` and `surface` when
moving a complete color/canvas system. Importing surface data invalidates both
editor recipes rather than silently pretending their controls still describe it.

**Copy share link** puts a compressed version-1 configuration in the URL fragment;
it needs no account and does not upload the configuration to a storage service.
Links restore the theme and editor recipes, including after reload. Specimen form
data is excluded. **Reset preview** restores the default workspace and clears its
share fragment. Files and expanded links are limited to 256 KiB; links also have
a 16,000-character transport limit. Use a configuration file when a link is too
large. Invalid, unsupported or damaged input leaves the current theme intact.

The optional scoped CSS output contains the actual compiled light/dark values.
Load it after Radiant’s compiled styles and use the documented plain wrapper;
React/nested mode scopes should use the typed theme. CSS export rejects text that
cannot be safely represented as declarations, while the typed theme and JSON
remain available. A failed clipboard action leaves selectable output fields.

Font family names and requirements travel with themes, configurations and links;
font files stay local. Load required fonts in the consuming app. The setup panel
lists local/catalog/system descriptors, weights and styles when available. The
same document sections retain existing typography and motion values and component
exceptions for the later typesetting and spring tools.

## Inspect the result

Switch between an article, profile form, dense dashboard with a semantic table,
landing page and everyday components. Preview mode and width belong to the
inspection controls and never change the theme document. Phone width is capped
by the available space; its specimens respond to their container.

Each specimen keeps its own interaction state when you switch views or edit the
theme. **Reset specimen** resets only the selected example. The frame's **Reset
preview** restores the complete workspace, including controls and specimen state,
while keeping source inspection open. Component states include invalid, disabled
and pending; use the keyboard to inspect focus. Motion respects the operating
system's reduced-motion preference.

## Package availability

The site consumes the exact published **Radiant 0.0.4** package from npm. The
complete palette, spacing/surfaces and handoff editors use its public document,
generation and appearance APIs. No library source, Storybook module or workspace
alias is imported.

The repository can also inspect a future packed library build with
`pnpm preview:candidate /absolute/path/radiant.tgz`. Such previews display an
explicit **Local candidate** label; they do not change the public dependency pin.
