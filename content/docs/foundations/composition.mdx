title: Composition
description: Keep native behavior, state ownership and styling responsibilities explicit.

Radiant components keep native HTML behavior. Your application owns state,
validation, requests and persistence. The
[profile form recipe](/docs/recipes/profile-form/) uses the same fields with
native React and TanStack Form, standalone or inside a Card or Dialog.

## Choose one state owner

| State                           | Browser-owned initial state | Application-owned state   |
| ------------------------------- | --------------------------- | ------------------------- |
| Input text                      | `defaultValue`              | `value` + `onChange`      |
| Checkbox selection              | `defaultChecked`            | `checked` + `onChange`    |
| RadioGroup selection            | `defaultValue`              | `value` + `onValueChange` |
| Dialog / Collapsible visibility | `defaultOpen`               | `open` + `onOpenChange`   |
| Accordion selection             | `defaultValue`              | `value` + `onValueChange` |

Keep each state axis under one owner for the instance's lifetime. Do not pass
both the controlled value and the default, or switch ownership on rerender.
Defaults are initial snapshots. Remount with a new `key` to change owner or
Accordion selection type.

Native form reset restores uncontrolled controls. A controlled form's owner
must reset its values, validation and touched/submission metadata. Form reset
does not own Dialog visibility or a disclosure's open state. Closed Collapsible
content stays mounted, keeping its state and form participation.

## Events are observations and requests

Input and Checkbox use native change/blur events. Disclosure state follows
native details toggles. Controlled callbacks request a change; the owner
accepts it by updating its prop. Prop synchronization and no-op requests are
not fresh user changes.

For cancellable actions, guards run first, then your handler, then the
uncancelled library request. Calling `preventDefault()` in the supported
activation handler vetoes the request. Disabling a component keeps its native
guard; styling something as disabled does not disable it. See
[Dialog](/docs/dialog/) and [Accordion](/docs/accordion/) for examples.

Field connects labels, descriptions and errors, but does not decide when to
validate. Keep validation, touched state and save feedback with the form owner,
as the [Field adapter example](/docs/field/) does.

## Anatomy, styles and refs

Props and refs target the real native host, not a label wrapper. The family
pages have complete anatomy and prop tables.

| Family / part            | Native target                           | Composition responsibility                                    |
| ------------------------ | --------------------------------------- | ------------------------------------------------------------- |
| Button / Link            | `button` / `a`                          | Actions versus navigation; Button defaults to `type="button"` |
| Input / Checkbox / Radio | `input`                                 | Values, focus, native form participation                      |
| Field                    | `div`, or grouped `fieldset` / `legend` | Connected label, help and error anatomy                       |
| RadioGroup               | `fieldset` / `legend`                   | Native radio grouping and selection ownership                 |
| Dialog / DialogContent   | Context without a host / `dialog`       | Compose title, description and real actions                   |
| Collapsible / trigger    | `details` / `summary`                   | Browser disclosure behavior                                   |
| Accordion                | Group of Collapsibles                   | Single or multiple selection coordination                     |
| Card                     | `div`                                   | Passive surface; actions remain real controls inside it       |

### Replacing an action host

Button, Link and Dialog actions offer typed `render` callbacks. Return one
compatible element that forwards every resolved prop, ref, handler, style and
child to a real button or anchor. Radiant rejects directly incompatible native
hosts; custom adapters must still honor the contract. Start from
[Link's Next.js adapter](/docs/link/) or
[Button's host replacement example](/docs/button/).

## Functional CSS

Keep closed `dialog` and `details`
content hidden, constrain dialog geometry and scrolling, and keep the real
input and its hit target available. Do not remove labels, focus rings or
invalid, pending and disabled cues. Preserve forced-colors system colors and
reduced-motion alternatives in replacement styles.

Use [semantic tokens and local overrides](/docs/foundations/theming/#semantic-tokens-and-exceptions)
for presentation changes. On the Tailwind route, matching caller utilities
merge with component defaults; the ordinary CSS cascade still applies. These
behaviors do not need the optional reset.

## Client and server responsibilities

Radiant's interactive modules declare their own `'use client'` boundaries; the
package entry and theme data are server-safe. A Next.js server layout may import
the global stylesheet and render an interactive Radiant component. Your own
module needs `'use client'` when it uses hooks, event handlers or browser APIs.

Themes from `defineTheme` can cross the server/client boundary. System mode
uses CSS media queries; do not branch the initial render on `window.matchMedia`. Keep initial values, ownership and generated IDs
consistent through hydration.

Collapsible's `defaultOpen` is reflected in server HTML. Dialog renders closed
on the server and opens with native `show()` or `showModal()` after mounting;
do not add a server `open` attribute.
Application handlers and coordinated state need hydration; native links and
basic details disclosure work before it. On static hosting, keep submissions
disabled until their client handler is ready, as the recipe does.

The [architecture](https://github.com/cognitap/radiant/blob/main/docs/architecture.md)
and [React bindings reference](https://github.com/cognitap/radiant/blob/main/docs/react-bindings.md)
cover the complete lifecycle contract.
