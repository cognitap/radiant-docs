Semantic tokens describe your system; component overrides express exceptions.
Apply a theme to the subtree that needs it, after the
[stylesheet setup](/docs/getting-started/#choose-a-styling-route).

## Example themes

Radiant's core entry ships `defaultTheme`. The other presets are examples to
use or copy, from `@cognitap/radiant/examples`, and the
[theme workshop](/docs/workshop/) starts from the same ones. Its readonly
`themes` registry lists all nine. Changing presentation preserves a form's
state.

Import a preset by its named export from `@cognitap/radiant/examples`. Store a selection by its stable `id`, not
its name. A theme does not install fonts or change a control's semantic role.

### Fonts and browser fallbacks

Radiant never downloads preset fonts. Load weights 400, 600 and 700 yourself,
plus 550 for Default and Radiant and Archivo Black for Sharp 3D actions.

Glass uses translucent surfaces and a gradient canvas, so surrounding content
affects its appearance. Browsers without `corner-shape` fall back to rounded
corners.

## Author a theme

Garden is an example theme, not a library preset. Its shared `control.radius`
affects Input and Button; `components.button.radius` changes only Button.

<FoundationDemo kind="authoring" />

`defineTheme` takes a lowercase slug `id`, a nonempty `name`, partial `tokens`,
optional `components` and light/dark `modes`. It returns immutable,
JSON-serializable data. Unknown groups and keys fail typechecking and throw at
runtime. CSS values must be nonempty strings, numeric effects finite,
and opacity between 0 and 1. You own CSS grammar
and contrast.

Each mode resolves **library mode defaults → common theme values → mode
overrides**. A common accent overrides both modes unless the dark mode sets
its own value.

### Semantic tokens and exceptions

Shared token groups are `color`, `typography`, `control`, `surface`, `focus`,
`motion`, `spacing` and `state`. Prefer these roles for changes across families.
Components resolve **local component override → shared semantic role → neutral
baseline**.

| Authoring path              | Public CSS variable       | Scope of the change         |
| --------------------------- | ------------------------- | --------------------------- |
| `tokens.color.accent`       | `--rad-color-accent`      | Shared accent palette       |
| `tokens.control.radius`     | `--rad-control-radius`    | Shared control shape        |
| `tokens.typography.family`  | `--rad-typography-family` | Shared typography           |
| `components.button.radius`  | `--rad-button-radius`     | Button's radius             |
| `components.radioGroup.gap` | `--rad-radio-group-gap`   | Space between radio options |

Reusable exceptions use the `ThemeComponentOverrides` type; local styles can
use `ThemeStyle`, with typed CSS and custom properties.
`radio.labelGap` spaces an option's label; `radioGroup.gap` spaces the options.
Checkbox caps inherited rounding to stay a box, and Radio stays circular unless
overridden. Variables beginning `--_` are private.

### Roles

A role reads one token group and reaches every family that plays it:
`control.action` for actions, `control.field` for wells, `control.selected`
for the chosen tab, segment or page. See the
[roles reference](https://github.com/cognitap/radiant/blob/main/docs/theming.md#roles).

## Nested scopes

`ThemeScope` renders a `div`, accepts native props and a ref, and paints canvas,
foreground and body typography inside its subtree. It does not change the
document, persist preferences or install mode listeners. A native top-layer
Dialog remains in its original DOM scope.

<FoundationDemo kind="scopes" />

Omit `theme` or `mode` to inherit it. A scope with neither follows ordinary CSS
inheritance. A scope
with `theme={defaultTheme}` resets the theme and component effects. At the
root, the stylesheet follows the system preference. `mode="system"` uses CSS
media queries, so server markup and the first client render match.

Known theme variables, such as `--rad-control-radius`, set in an ancestor
ThemeScope's `style` survive mode-only scopes. A new named theme starts from
library defaults and clears inherited exceptions. A preset's explicit component
radius can take precedence over the shared radius.

Explicit inline styles win on their own scope host. Token overrides from
ordinary stylesheet rules or DOM wrappers are lost when a mode-only scope
re-materializes the theme. Put an exception that must survive into the theme
or a ThemeScope's inline `style`. Other properties, such as body font size,
follow normal CSS inheritance.

## Customize without breaking behavior

Before replacing a host or broad styling rules, read the
[functional CSS](/docs/foundations/composition/#functional-css) to keep.
The [theming reference](https://github.com/cognitap/radiant/blob/main/docs/theming.md)
has complete token and migration details.
