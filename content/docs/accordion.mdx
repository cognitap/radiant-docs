## Choose a selection model

Accordion coordinates [Collapsible](/docs/collapsible/) items. Each remains
native `details` with a direct-child `summary`. The root owns selection; each
item has a distinct `value`.

Single selection opens at most one item. Open Themes and modes and Installation
closes; activate the same summary again to leave all items closed. Multiple
selection allows both to stay open. Change Selection in the preview to compare.
Changing Selection or State owner starts a fresh example because Accordion's
type and ownership stay fixed during a mount.

## Keyboard, disabled state and content

Use Tab to reach enabled summaries and links in open content. Enter and Space
toggle the focused summary. Native disclosures use ordinary tab order; arrow
keys do not implement a separate Accordion focus-navigation scheme here.
Closed content stays mounted and is hidden from normal keyboard navigation.

Future integrations is disabled. Its summary has `aria-disabled`, is removed
from the tab sequence and guards pointer/Enter/Space activation. The Disabled
option applies that policy to every item. Disabled state prevents user changes;
it does not replace your application's ownership of selection.

Basic native details can expand without JavaScript. Coordinated single/multiple
selection, disabled guards, controlled state and preview feedback require
JavaScript. Import the functional compiled stylesheet to preserve closed-content
and focus behavior.

## Controlled or local selection

Use `defaultValue` for local selection or `value` with `onValueChange` for a
controlled selection. In single mode the value is a string or `null`; in
multiple mode it is a string array. Use `null` or `[]` to clear the corresponding
controlled selection. Do not use `undefined` to clear it: that changes ownership.

The controlled example exposes Close all sections. It updates application
state, while summaries request updates through `onValueChange`. The same
copyable example supports both models. Give the Accordion a new key if changing
its `type` or ownership intentionally; do not control each item's `open` yourself.

## Named parts and targets

| Component        | Native style/ref target | `data-slot` tokens                      |
| ---------------- | ----------------------- | --------------------------------------- |
| Accordion        | `div`                   | `accordion`                             |
| AccordionItem    | `details`               | `collapsible accordion-item`            |
| AccordionTrigger | `summary`               | `collapsible-trigger accordion-trigger` |
| AccordionContent | `div`                   | `collapsible-content accordion-content` |

Match composed identities with token membership, such as
`[data-slot~="accordion-item"]`. The root exposes `data-type` and optional
`data-disabled`. Items expose `data-value`, optional `data-disabled` and
`data-state`; trigger/content also expose `data-state`.

AccordionTrigger places a heading **inside** the direct-child summary.
`level` defaults to `3`; choose a level from `1`–`6` to fit your document, or
`null` to omit the heading. Its native attributes, styles and ref still target
the summary. Compact adjusts Collapsible padding through the Accordion root's
inline theme token, inherited by its items. `useAccordion()` returns the nearest
owner state, or `null` outside an Accordion.

## Public props

These contracts match **Radiant 0.0.4**; each component's prop type,
`AccordionValue`, `AccordionHeadingLevel` and `AccordionState` are exported.

| Accordion prop           | Purpose / default                                                |
| ------------------------ | ---------------------------------------------------------------- |
| `type`                   | `single` (default) or `multiple`; fixed per mount                |
| `value` / `defaultValue` | Controlled or initial local selection; defaults to `null` / `[]` |
| `onValueChange`          | Receives the matching string-or-null / string-array selection    |
| `disabled`               | Disable user interaction for all items; defaults to `false`      |
| Native div props         | Root attributes, events, children, styling and ref               |

| Part prop                      | Purpose                                                                      |
| ------------------------------ | ---------------------------------------------------------------------------- |
| Item `value`                   | Required distinct string identifying this item                               |
| Item `disabled`                | Disable this item; root disabled state also applies                          |
| Item native props              | Details props/styles/ref, excluding owned open/defaultOpen/onOpenChange/name |
| Trigger `level`                | Inner heading level; default `3`, or `null`                                  |
| Trigger / Content native props | Summary/div props, styles and refs                                           |
| `data-slot`                    | Additive identities on root and named parts                                  |

## Use the example

Install `@cognitap/radiant@0.0.4` and import `@cognitap/radiant/styles.css` once.
View source displays the actual component, shared types and CSS; preserve the
`compositions/` paths when copying. It needs React and Radiant only.

Theme/mode and Compact preserve selection. Reset preview restores single,
uncontrolled selection with Installation open. For an independent disclosure,
use [Collapsible](/docs/collapsible/); for passive grouping of content and actions,
use [Card](/docs/card/).
