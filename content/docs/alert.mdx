## Usage

Use Alert for a message that must stay in the page. Use [Toast](/docs/toast/) to confirm or report something the user just did, and [AlertDialog](/docs/alert-dialog/) for a decision the user must make before continuing. Use [Field](/docs/field/) for an error tied to one control.

```tsx
<Alert tone="warning">
  <AlertTitle>Connection interrupted</AlertTitle>
  <AlertDescription>Your changes remain on this device until you reconnect.</AlertDescription>
</Alert>
```

`tone` only sets color: `neutral` (default) for information, `accent` for success or confirmation, `warning` for a problem the user can still avoid, and `danger` for a failure. There is no `success` or `info` tone. Say the outcome in the text; color only reinforces it.

## State

Alert holds no state and contributes no form value. It has no timers and never dismisses itself, so remove it from your own state when the message no longer applies.

## Accessibility

`announce` chooses urgency, independently of tone:

| announce        | Role     | Use for                                        |
| --------------- | -------- | ---------------------------------------------- |
| `off` (default) | None     | Static information present when the page loads |
| `polite`        | `status` | Nonurgent results, such as "Draft saved"       |
| `assertive`     | `alert`  | Problems that need attention now               |

Both live roles are implicitly live and atomic, so Alert renders no `aria-live` or `aria-atomic`, and its types reject them. Mount a live Alert empty before the message arrives, then update its children in place. Keep `announce` and `key` stable. Give live alerts `aria-label` or `aria-labelledby`. A named static Alert becomes a `group`.

Alert never takes or moves focus. Keep recovery controls outside the live region so updates don't repeat their names.

| Key             | Behavior                               |
| --------------- | -------------------------------------- |
| Tab / Shift+Tab | Move through controls inside the Alert |

## Motion

Background, text and border colors transition over `--rad-motion-color-duration`. Reduced motion removes the transition. Alert has no enter or exit animation.

## Styling

| Part             | Element              | data-slot           | Data attributes              |
| ---------------- | -------------------- | ------------------- | ---------------------------- |
| Alert            | `div`                | `alert`             | `data-tone`, `data-announce` |
| AlertTitle       | `h1`–`h6` by `level` | `alert-title`       | None                         |
| AlertDescription | `p`                  | `alert-description` | None                         |

Each part takes `className`, `style` and a native ref. `components.alert` or `--rad-alert-*` variables set radius, padding, gap, background, color, borderColor, borderWidth, borderStyle, shadow, titleSize, titleWeight and descriptionSize. Forced colors use system text and canvas colors.

## API

| Alert prop       | Type                                   | Default         |
| ---------------- | -------------------------------------- | --------------- |
| tone             | neutral / accent / warning / danger    | neutral         |
| announce         | off / polite / assertive               | off             |
| style            | ThemeStyle                             | None            |
| Native div props | Except role, aria-live and aria-atomic | Native defaults |

| AlertTitle prop | Type                  | Default         |
| --------------- | --------------------- | --------------- |
| level           | 1 / 2 / 3 / 4 / 5 / 6 | 2               |
| style           | ThemeStyle            | None            |
| Native h2 props | Includes className    | Native defaults |

AlertDescription takes `style` and native `<p>` props.

Exports: `Alert`, `AlertTitle`, `AlertDescription`; types `AlertProps`, `AlertTitleProps`, `AlertDescriptionProps`, `AlertTone`, `AlertAnnouncement`, `AlertHeadingLevel`.
