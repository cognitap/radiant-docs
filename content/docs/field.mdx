## One control

Field connects its label to the control's ID, joins help and error IDs in
`aria-describedby`, and marks the control invalid when `error` has content.
[Input](/docs/input/), [Checkbox](/docs/checkbox/) and Radio connect automatically.

```tsx
<Field
  label="Email"
  description="Your work address"
  error={error}
  required
>
  <Input
    name="email"
    type="email"
  />
</Field>
```

You own values, touched state, validation, submission and focus. Use `noValidate`
on the form for custom feedback. Required adds native metadata and an indicator;
disabled controls are omitted from native form data. A child cannot undo its
Field's required or disabled state.

## Native or custom controls

Forward every callback prop to one native control. Merge the callback's
`aria-describedby` with any external description IDs. Radiant controls append
external IDs once.

```tsx
<Field
  label="Address"
  controlId="address"
  error={error}
>
  {control => (
    <input
      {...control}
      ref={inputRef}
      name="address"
    />
  )}
</Field>
```

Field's own `id` and `ref` target its wrapper. Put a control ref on the input.
`useField()` returns the nearest `FieldState`, or `null` outside Field.
Its `controlProps` contains the callback metadata in control layout.

## Groups

```tsx
<Field
  layout="group"
  label="Channels"
  required
  error={channelError}
>
  <Checkbox
    label="Email"
    name="channels"
    value="email"
  />
  <Checkbox
    label="Team feed"
    name="channels"
    value="feed"
  />
</Field>
```

A group is a native `fieldset` with a `legend`. Each child needs its own label.
Group help and errors describe the fieldset. Required does not require every
checkbox: implement “choose at least one” in your form. Disabled propagates to
nested Fields and Radiant controls. Groups have no `controlId` or children
callback; `useField().controlProps` is `null`. Use [RadioGroup](/docs/radio-group/)
for one choice.

## Motion

Import `useSpringLayout` from `@cognitap/radiant/motion/react`. Put each Field
inside a dedicated motion part and stable layout slot, as in the first example.
Animate surrounding space, keeping Field's grid and input at their natural size.
Errors, relationships and focus update immediately. Theme motion off and live
system reduced motion snap layout to its target. See [layout motion](/docs/foundations/motion/#animate-layout).

## Props and parts

`FieldProps`, `FieldControlProps`, `FieldState` and `FieldLayout` are exported.

| Prop                                      | Purpose / default                                                       |
| ----------------------------------------- | ----------------------------------------------------------------------- |
| `label`                                   | Required control label or group legend                                  |
| `layout`                                  | `control` (default) or `group`                                          |
| `controlId`                               | Input ID; otherwise generated                                           |
| `description`, `error`                    | Optional help / consumer-owned validation content                       |
| `required`, `disabled`                    | Both default to `false`                                                 |
| `requiredIndicator`                       | Decorative content; default `*`                                         |
| `children`                                | Content; control layout also accepts `(FieldControlProps) => ReactNode` |
| `parts`                                   | Presentation hooks below                                                |
| Native props, `className`, `style`, `ref` | Target the root; group accepts `form` / `name`                          |

| Part          | Native target / `data-slot`          |
| ------------- | ------------------------------------ |
| Root          | `div` / `fieldset`; includes `field` |
| `label`       | `label` / `legend`; `field-label`    |
| `description` | Help `div`; `field-description`      |
| `error`       | `div role="alert"`; `field-error`    |
| `required`    | Decorative `span`; `field-required`  |

Parts accept `className` and `style`; Field keeps IDs and ARIA. Root
`data-layout` identifies the layout. `data-required`, `data-disabled` and
`data-invalid` are presence attributes.
