## Content with explicit actions

Card is a passive `div` surface. Header, Content and Footer organize its
children; they add no click behavior, selection or focus management. The whole
Card is not an interactive target.

Use [Button](/docs/button/) for actions and [Link](/docs/link/) for
destinations inside it. Avoid putting controls inside a clickable card wrapper.
If the grouping needs an article or region role, compose that semantic HTML
around it; Card does not assign one.

## Anatomy and customization

| Component       | Native host / style and ref target | `data-slot` token  |
| --------------- | ---------------------------------- | ------------------ |
| Card            | `div` surface                      | `card`             |
| CardHeader      | `div`                              | `card-header`      |
| CardTitle       | Heading, default `h2`              | `card-title`       |
| CardDescription | `p`                                | `card-description` |
| CardContent     | `div`                              | `card-content`     |
| CardFooter      | `div` with wrapping action layout  | `card-footer`      |

CardTitle's `level` accepts `1`–`6` and changes the heading host. Each part
accepts native attributes/events, `className`, typed theme `style`, ref and
additive `data-slot` identities. These are separate named components, not a
root `parts` object.

Set `--rad-card-padding` in Card's inline style to change its padding. Shared
surface tokens set its background, shape, spacing and shadow; child actions
keep their own family contracts.

## Public props

Every part's prop type and `CardHeadingLevel` are exported.

| Prop                 | Applies to / purpose                                             |
| -------------------- | ---------------------------------------------------------------- |
| `children`           | Content for each named part                                      |
| `level`              | CardTitle only; `1`–`6`, default `2`                             |
| `className`, `style` | Each component's actual host, including local theme tokens       |
| `ref`                | Each component's native host; not redirected to a child control  |
| `data-slot`          | Additional identity tokens; retains the part's base identity     |
| Other native props   | Attributes/events of the corresponding div, heading or paragraph |

Card has no open, selected or disabled state. Put those on the form, action,
[Dialog](/docs/dialog/) or [disclosure](/docs/collapsible/) that owns the
interaction. Styling a passive surface does not disable its children.

## Use the examples

Keep the `compositions/` and `profile/` paths when copying. The focused Card
example needs only React and Radiant. Its native link works without JavaScript;
the bookmark feedback needs it. The profile selector also imports optional
TanStack Form; the [recipe setup](/docs/recipes/profile-form/#use-the-recipe)
covers native-only and TanStack copies. No example persists or sends data.
