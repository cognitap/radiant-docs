## Give content a home

```tsx
<Card>
  <CardHeader>
    <CardTitle level={2}>Studio notes</CardTitle>
    <CardDescription>Keep the next step close.</CardDescription>
  </CardHeader>
  <CardContent>A little room for a good idea.</CardContent>
  <CardFooter>
    <Button onClick={save}>Save note</Button>
    <Link href="/projects">All projects</Link>
  </CardFooter>
</Card>
```

Card is a passive div. Its named parts organize content without adding
selection, focus management or click behavior. Put [Button](/docs/button/)
actions and [Link](/docs/link/) destinations inside. Keep controls out of
clickable wrappers. Compose an article or named region around Card when needed.

CardTitle defaults to h2; choose `level` for the surrounding page outline,
independently of visual size. Cards in a list often use h3 beneath a section h2.

## Add measured layout motion

```tsx
import { useRef } from 'react'
import { Card } from '@cognitap/radiant'
import { useSpringLayout } from '@cognitap/radiant/motion/react'

function Projects({ items }: { items: { id: string; title: string }[] }) {
  const root = useRef<HTMLDivElement>(null)
  useSpringLayout(root)

  return (
    <div
      ref={root}
      style={{ display: 'grid', gap: '1rem' }}
    >
      {items.map(item => (
        <div
          key={item.id}
          data-rad-layout-slot=""
          style={{ display: 'flow-root' }}
        >
          <div data-rad-layout-part="">
            <Card>{item.title}</Card>
          </div>
        </div>
      ))}
    </div>
  )
}
```

The hook measures natural-flow slots together and animates resize and reorder.
Use stable keys and one dedicated part per slot. Text reflows without scaling;
inputs, selection and form submission stay native. Content appears or hides
immediately. The application restores focus after reordering.

Only the dedicated part animates size and translation;
Card's styles and refs still belong to its div. Keep slots borderless and
unpadded, and both wrappers free of transforms, transitions and outer margins.
Avoid scaled or rotated ancestors and nested layout groups. See the
[shared layout contract](/docs/foundations/motion/#animate-layout).

Theme motion off and live reduced motion settle layout immediately. Server
markup stays in natural flow. Card needs no motion prop or provider; the
optional provider enhances child actions separately.

## Parts and customization

| Component       | Native style/ref target | Identity         |
| --------------- | ----------------------- | ---------------- |
| Card            | div                     | card             |
| CardHeader      | div                     | card-header      |
| CardTitle       | Heading, default h2     | card-title       |
| CardDescription | p                       | card-description |
| CardContent     | div                     | card-content     |
| CardFooter      | div, wrapping actions   | card-footer      |

Each named part accepts native props, className, typed theme style, ref and
additive `data-slot` tokens. Caller classes and styles override defaults.
These are components, not a root parts map. Set `--rad-card-padding` or
`--rad-card-gap` locally; shared surface and typography roles supply defaults.
Preserve visible focus and leave room around child controls.

## Forms and state

Put a form in CardContent and give it explicit submit/reset actions. The form
owns validation, values and persistence. Card has no open, selected, pending or
disabled state; disabling a surface cannot disable its children. Use
[Dialog](/docs/dialog/) or [Collapsible](/docs/collapsible/) for those behaviors.
The same [profile recipe](/docs/recipes/profile-form/) works in all three placements.

## Public props

Every part's prop type and CardHeadingLevel are exported.

| Prop               | Applies to / purpose                       |
| ------------------ | ------------------------------------------ |
| children           | Every named part                           |
| level              | CardTitle heading 1–6; default 2           |
| className, style   | Actual host, including local theme tokens  |
| ref                | Actual div, heading or paragraph           |
| data-slot          | Additional identity tokens                 |
| Other native props | Corresponding host's attributes and events |

their accompanying paths; the profile recipe documents its optional form adapter.
