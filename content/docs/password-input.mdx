## Usage

Use PasswordInput for credentials that can be revealed temporarily. Use [Input](/docs/input/) for ordinary text and [OTPField](/docs/otp-field/) for verification codes.

```tsx
<Field
  label="Password"
  required
>
  <PasswordInput
    name="password"
    autoComplete="current-password"
  />
</Field>
```

Use new-password for account creation or replacement, and username on the associated account input. Keep stable names and IDs for password-manager autofill. Applications own authentication, validation and requests.

## State

Choose value with onChange or defaultValue for the native value owner. Values are strings; an empty password is an empty string. Prop synchronization emits no change event. Native reset restores uncontrolled values; controlled consumers reset their own values.

Visibility starts hidden and belongs to PasswordInput. Reveal keeps the same native input, value, autofill attributes and selection. Native submit and reset events hide it, including cancelled events and externally associated forms. Use requestSubmit() for programmatic submission; form.submit() skips submit events.

Disabled Fields disable both input and reveal Button and hide the password. Read-only inputs can still be revealed. The connection example remounts on record changes to start each credential hidden.

## Accessibility

[Field](/docs/field/) supplies the label, help and error relationships. Native password-input semantics remain browser-owned. The reveal Button changes between its Show and Hide labels and identifies its input with aria-controls. Keep meaningful showLabel and hideLabel strings.

| Key                     | Behavior                             |
| ----------------------- | ------------------------------------ |
| Tab / Shift+Tab         | Visit the input and reveal Button    |
| Space / Enter on reveal | Toggle visibility without submitting |
| Enter in input          | Follow native form submission        |

Visibility adds no live announcement or focus movement. Consumer feedback should describe the request without echoing the password.

## Motion

Visibility changes immediately. The reveal Button uses motion off. Other example Buttons retain their own motion behavior.

## Styling

className, style, native events and ref target the actual input. The input retains input, input-group-input and password-input slot tokens. Named wrapper and toggle parts style the real InputGroup and Button; they add password-input-wrapper and password-input-toggle identities.

Input, InputGroup and Button themes apply through real composition. `components.passwordInput.gap` provides `--rad-password-input-gap` for spacing.

## API

### PasswordInput

| Prop                           | Type / default                                    |
| ------------------------------ | ------------------------------------------------- |
| value / defaultValue           | string; one native owner                          |
| onChange                       | Native input change event                         |
| autoComplete                   | Native autocomplete tokens; current-password      |
| showLabel / hideLabel          | Nonempty strings; Show password / Hide password   |
| controlSize                    | small / medium / large; medium                    |
| disabled / required / readOnly | Native booleans; Field adds disabled and required |
| form / name                    | Native form association and submitted name        |
| parts                          | wrapper / toggle; className and ThemeStyle        |
| className / style / ref        | Native input / ThemeStyle / HTMLInputElement      |
| Other props                    | Input props except type and children              |
